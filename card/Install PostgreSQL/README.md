## Требования

- Операционная система: Windows 10/11 или Windows Server 2016/2019/2022
- Права администратора на компьютере
- Свободное место на диске: минимум 2 ГБ
- PostgreSQL версии 15 (установлен в `D:\PostgreSQL\15`)
- Python 3.8+ (если используется приложение с Python)
- Приложение установлено в `D:\card`

## Установка PostgreSQL

### Шаг 1: Скачивание установщика

1. Перейдите на официальный сайт PostgreSQL: https://www.postgresql.org/download/windows/
2. Выберите версию для Windows (рекомендуется последняя стабильная, например, PostgreSQL 15)
3. Скачайте установочный файл `.exe`

### Шаг 2: Установка PostgreSQL

1. Запустите скачанный установочный файл от имени администратора
2. Нажмите "Next" на экране приветствия
3. **Важно:** Укажите путь установки: `D:\PostgreSQL\15\`
4. **Важно:** Запомните пароль, который вы зададите для пользователя `postgres` (в данном случае используется пароль `3831043`) — он понадобится для настройки
5. Порт оставьте по умолчанию: `5432`
6. Locale выберите `Russian, Russia` или `English, United States` в зависимости от требований
7. Нажмите "Next" и дождитесь завершения установки
8. Уберите галочку с "Stack Builder" (если не планируете устанавливать дополнительные компоненты) и нажмите "Finish"

### Шаг 3: Проверка установки

Откройте командную строку (cmd) от имени администратора и выполните:

```cmd
"D:\PostgreSQL\15\bin\psql.exe" -U postgres
```

Введите пароль, заданный при установке. Если подключились успешно — установка прошла успешно.

Выйдите из psql командой `\q`

## Настройка базы данных

### Шаг 1: Создание базы данных

Откройте командную строку от имени администратора и выполните:

```cmd
"D:\PostgreSQL\15\bin\createdb.exe" -U postgres card_system
```

Введите пароль пользователя `postgres` (по умолчанию используется `3831043`).

### Шаг 2: Создание пользователя приложения

```cmd
"D:\PostgreSQL\15\bin\psql.exe" -U postgres -c "CREATE USER app_user WITH PASSWORD 'your_secure_password';"
```

Замените `your_secure_password` на надежный пароль.

### Шаг 3: Предоставление прав

```cmd
"D:\PostgreSQL\15\bin\psql.exe" -U postgres -c "GRANT ALL PRIVILEGES ON DATABASE card_system TO app_user;"
```

### Шаг 4: Инициализация схемы БД

Выполните SQL-скрипт инициализации (файл `init.sql` из корневой папки проекта):

```cmd
"D:\PostgreSQL\15\bin\psql.exe" -U postgres -d card_system -f "D:\card\postgres\init.sql"
```

Замените путь на актуальный путь к файлу `init.sql`.

## Миграция данных

Если у вас есть существующие данные в другой СУБД (например, SQLite), выполните следующие шаги:

### Вариант 1: Использование скрипта миграции (Python)

1. Установите необходимые зависимости:

```cmd
pip install psycopg2-binary sqlalchemy
```

2. Настройте подключение в вашем приложении, указав параметры PostgreSQL:

```python
DATABASE_URL = "postgresql://app_user:your_secure_password@localhost:5432/card_system"
```

3. Запустите скрипт миграции (если предусмотрен в проекте).

### Вариант 2: Ручной экспорт/импорт

Для SQLite → PostgreSQL:

1. Экспортируйте данные из SQLite в CSV:
```sql
.mode csv
.output data.csv
SELECT * FROM your_table;
```

2. Импортируйте в PostgreSQL через psql:
```sql
\COPY your_table FROM 'C:/path/to/data.csv' WITH CSV HEADER;
```

### Быстрый старт

1. **Автоматическая миграция (рекомендуется):**

   Следуйте инструкциям в файле `MIGRATION_GUIDE.md`.

## Как определить, какая база данных используется

Приложение может работать в двух режимах:

### Режим 1: Локальная база данных (папка Data)
- Данные хранятся в JSON-файлах в папке `D:\card\data\`
- Не требуется установка PostgreSQL
- Подходит для тестирования и небольших объемов данных

### Режим 2: PostgreSQL
- Данные хранятся в СУБД PostgreSQL
- Требуется установленный PostgreSQL
- Подходит для промышленной эксплуатации

### Переключение между режимами

**Способ 1: Через переменную окружения USE_POSTGRES**

Перед запуском приложения установите переменную окружения:

```cmd
REM Для PostgreSQL:
set USE_POSTGRES=true
set DB_HOST=localhost
set DB_PORT=5432
set DB_NAME=transport_cards
set DB_USER=postgres
set DB_PASSWORD=3831043
python app.py

REM Для локальной БД:
set USE_POSTGRES=false
python app.py
```

**Способ 2: Использование готовых скриптов запуска**

В папке `Install PostgreSQL` находятся два готовых скрипта:

- **`run_with_postgres.bat`** — запускает приложение с подключением к PostgreSQL
- **`run_with_local.bat`** — запускает приложение с локальной базой (папка Data)

Просто запустите нужный скрипт двойным кликом.

**Способ 3: Проверка в интерфейсе приложения**

После запуска приложения в левой нижней части боковой панели отображается индикатор подключения:
- 🟢 **PostgreSQL** — подключение к PostgreSQL
- 🔵 **MySQL** — подключение к MySQL (если реализовано)
- ⚫ **Локальная (Data)** — локальные JSON-файлы

## Настройка автоматического резервного копирования

### Шаг 1: Создание скрипта резервного копирования

Создайте файл `backup_daily.bat` в папке `C:\PostgreSQL\Backups\` (создайте папку заранее):

```batch
@echo off
REM daily_backup.bat - Скрипт ежедневного резервного копирования PostgreSQL

REM Настройки
set PG_BIN=D:\PostgreSQL\15\bin
set PG_USER=postgres
set PG_PASSWORD=your_postgres_password
set DB_NAME=card_system
set BACKUP_DIR=C:\PostgreSQL\Backups
set DATE=%DATE:~-4,4%%DATE:~-7,2%%DATE:~-10,2%_%TIME:~0,2%%TIME:~3,2%
set BACKUP_FILE=%BACKUP_DIR%\backup_%DB_NAME%_%DATE%.sql

REM Замена пробелов во времени на нули
set BACKUP_FILE=%BACKUP_FILE: =0%

REM Создание директории если не существует
if not exist "%BACKUP_DIR%" mkdir "%BACKUP_DIR%"

REM Выполнение резервного копирования
"%PG_BIN%\pg_dump.exe" -U %PG_USER% -d %DB_NAME% -F c -b -v -f "%BACKUP_FILE%"

REM Проверка успешности
if %ERRORLEVEL% EQU 0 (
    echo [%DATE% %TIME%] Резервная копия успешно создана: %BACKUP_FILE%
) else (
    echo [%DATE% %TIME%] Ошибка создания резервной копии!
    exit /b 1
)

REM Удаление старых резервных копий (хранить последние 7 дней)
forfiles /p "%BACKUP_DIR%" /s /m backup_*.sql /d -7 /c "cmd /c del @path"
```

**Важно:** Замените `your_postgres_password` на реальный пароль пользователя postgres.

### Шаг 2: Настройка переменной окружения PGPASSWORD (опционально)

Чтобы не вводить пароль каждый раз, можно установить переменную окружения:

```cmd
setx PGPASSWORD "3831043"
```

Или модифицировать скрипт, добавив перед вызовом pg_dump:

```batch
set PGPASSWORD=3831043
```

### Шаг 3: Планирование задачи в Планировщике заданий Windows

1. Откройте **Планировщик заданий**:
   - Нажмите `Win + R`, введите `taskschd.msc`, нажмите Enter
   
2. В правой панели выберите **"Создать задачу..."**

3. **Вкладка "Общие":**
   - Имя: `PostgreSQL Daily Backup`
   - Описание: `Ежедневное резервное копирование базы данных card_system`
   - Выберите: "Выполнять для всех пользователей"
   - Выберите: "Выполнять с наивысшими правами"
   - Конфигурация: выберите вашу версию Windows

4. **Вкладка "Триггеры":**
   - Нажмите "Создать..."
   - Начать задачу: "По расписанию"
   - Настроить: "Ежедневно"
   - Время начала: например, `02:00` (ночью, когда нагрузка минимальна)
   - Повторять каждые: не заполнять
   - Нажмите "OK"

5. **Вкладка "Действия":**
   - Нажмите "Создать..."
   - Действие: "Запуск программы"
   - Программа или сценарий: `C:\Windows\System32\cmd.exe`
   - Добавить аргументы: `/c "C:\PostgreSQL\Backups\backup_daily.bat"`
   - Начать в: `C:\PostgreSQL\Backups\`
   - Нажмите "OK"

6. **Вкладка "Условия":**
   - Рекомендуется снять галочку "Запускать только при питании от электросети" для серверов
   - Настройте остальные параметры по необходимости

7. **Вкладка "Параметры":**
   - Убедитесь, что стоит галочка "При сбое выполнения перезапустить через:"
   - Установите интервал: `5 минут`
   - Число попыток повторного запуска: `3`

8. Нажмите "OK" и введите пароль администратора при запросе

### Шаг 4: Проверка задачи

1. Найдите созданную задачу в списке Планировщика заданий
2. Щелкните правой кнопкой мыши → "Выполнить"
3. Проверьте папку `C:\PostgreSQL\Backups\` — должна появиться резервная копия
4. Проверьте журнал задач в Планировщике на наличие ошибок

## Устранение неполадок

### Проблема: Ошибка подключения "password authentication failed"

**Решение:**
1. Проверьте правильность пароля в скрипте备份
2. Убедитесь, что пользователь существует:
   ```cmd
   psql -U postgres -c "\du"
   ```
3. Проверьте файл `pg_hba.conf` (обычно в `D:\PostgreSQL\15\data\`):
   - Убедитесь, что есть строка: `host all all 127.0.0.1/32 scram-sha-256`
   - После изменений перезапустите службу PostgreSQL

### Проблема: Служба PostgreSQL не запускается

**Решение:**
1. Откройте "Службы" (`services.msc`)
2. Найдите службу `postgresql-x64-15` (или ваша версия)
3. Попробуйте запустить вручную
4. Проверьте логи в `D:\PostgreSQL\15\data\log\`

### Проблема: Задача в Планировщике не выполняется

**Решение:**
1. Проверьте права учетной записи, от которой выполняется задача
2. Убедитесь, что путь к скрипту указан верно
3. Проверьте журнал событий Windows (Event Viewer) → Журналы приложений и служб
4. Попробуйте запустить скрипт вручную от имени администратора

### Проблема: pg_dump не найден

**Решение:**
- Укажите полный путь к исполняемому файлу в скрипте
- Или добавьте путь в системную переменную PATH:
  ```cmd
  setx PATH "%PATH%;D:\PostgreSQL\15\bin"
  ```
